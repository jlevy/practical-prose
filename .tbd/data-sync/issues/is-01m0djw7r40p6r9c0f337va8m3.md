The repo's .claude/skills/pprose-* entries are relative symlinks into skills/ (all seven as of 7d14c2f, which converted pprose-review to match its six siblings). Symlinks are why that surface cannot drift, and a test asserts the shape.

But git symlinks do not materialize as links on Windows without core.symlinks=true or Developer Mode; a Windows clone gets plain text files containing the target path, so the skills silently do not load and test_claude_dogfood_skills_are_symlinks_into_discovery fails.

This predates the change (six of seven were already symlinks) but the change widened it to all seven. Options: (a) accept and document the Windows requirement, (b) mirror .claude/ as real copies the way .agents/ now is (flow 4 in devtools/sync_resources.py), losing drift-free-by-construction but gaining portability, (c) keep symlinks and skip the test on Windows.

Only affects contributors developing this repo on Windows; installed users get real copies from pprose install either way.
